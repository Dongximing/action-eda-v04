# 实验设计：重复动作的源头、只用历史提前发现、提前纠错 vs 循环后纠错

状态：设计稿（未执行）。所有数字都是计划或已有观察，结果栏一律留空。

## 0. 三个要证明的结论

| 编号 | 结论 | 要排除的另一种解释 |
|---|---|---|
| C1 | 大多数循环（连续重复同一动作）是由**更早**的一个源头错误引起的 | 循环是自己发生的（模型"卡住"），之前一切正常 |
| C2 | 只用**当前为止的历史**（不看未来、不问环境的标准答案）就能在循环开始前发现源头错误 | 只有等循环出现、或者看了未来/环境内部信息才能发现 |
| C3 | 在源头处纠错，比在循环开始后纠错更有效 | 两者一样；或者"提前"占优只是因为剩下的步数更多；或者任何一句额外提示都有用 |

## 1. 定义（全部可以用代码从日志算出来）

- **循环**：同一动作连续出现 ≥ k 次（主设置 k = 3；敏感性分析 k = 2、4），或者两个动作交替 A B A B 至少两轮。**循环起点 t_L** = 第一个循环的第一步。只看输掉的局；赢的局里的循环单独统计。
- **源头错误 e**：t_L 之前、最早的一步，**如果把这一步改对，这局就能救回来**。分两层标注：
  1. **规则标注（全量，便宜）**：从游戏回应文字读出，分为
     - 拿错东西：拿起的东西名字不是任务要的；
     - 前提不成立：动作失败（Nothing happens），而且失败原因是人不在那里、手里没东西或拿错东西、容器没开（用历史推出的状态判断）；
     - 探索停滞：从某一步起，连续 w 步没有新信息（w = 5），而目标还没看到。
  2. **反事实确认（抽样，花钱）**：在 e 处把动作换成"正确的下一步"（见 §4 的 oracle），agent 用同样的设置接着玩，看能不能赢。能救回来，就确认 e 是源头；救不回来，就把这个标注记为"未确认"。
- **提前**：报警的那一步 d 满足 e ≤ d < t_L。**提前量** = t_L − d（报警比循环早多少步）；**滞后** = d − e（比源头晚多少步）。

## 3. C1：循环是否由更早的错误引起

1. 每个输局找 t_L；在 t_L 之前找规则标注的最早错误 e。报告：有 e 的循环占比、e 的类别分布、e 到 t_L 的间隔分布。
2. **人工核对**：随机抽 40 个循环，两人独立标注"源头是哪一步、是什么错"，计算一致性（Cohen's κ），并和规则标注对比（准确率）。
3. **因果确认**（§4 的分支实验里的 O_e 组）：在 e 处换成正确动作，看循环是否消失、这局是否赢。**对照**：在 e 之前随机一步换成正确动作（安慰剂位置）；在 t_L 处换成正确动作。

**推翻 C1 的结果**：多数循环之前找不到 e；或者在 e 处改对，循环率并不比安慰剂位置更低。

## 4. 分支实验（C1 确认 和 C3 都用它）

利用缓存：从已保存的前缀**原样重放**到第 s 步（不花钱），在第 s 步注入干预，之后用新请求继续（花钱），直到赢或步数用完。

**干预类型**（时机和内容分开控制）：

| 代号 | 在哪一步 | 注入什么 |
|---|---|---|
| O_e | e（源头） | oracle：把这一步的动作换成正确动作 |
| O_L | t_L（循环起点） | 同上 |
| F_e | e | 文字反馈（检测器给的那句话，例如"mug 不是任务要的 cup"），动作仍由 agent 决定 |
| F_d | d（检测器报警的那一步） | 同 F_e 的文字 |
| F_L | t_L | 同一句文字反馈 |
| P_e | e | 安慰剂：一句不含信息的话（"Please continue."），控制"任何扰动都有用" |
| N | — | 不干预，从 e 起重新采样继续，估计 API 本身的随机性 |

**关键的公平性控制**：提前干预天然多出剩余步数。所以**所有组在干预之后都给相同的剩余步数 R**（R = 50 − e，循环起点组相应延长总步数），比较的是"同样剩余预算下的成功率"。另报一个不延长的版本。

**oracle 正确动作**：用 ALFWorld 自带的专家规划器（handcoded expert），在第 s 步的状态下给出下一步动作。需要先确认我们的环境封装能拿到它（工程项，见 §7）。

**重复次数**：温度 0 时 API 仍有随机性（官方 StateAct 的 game11 两次运行结果不同），每个条件每局跑 3 次，报告均值和区间。

## 5. C2：只用历史能否提前发现

**离线评测，不花钱**：在已有轨迹上，对每个 t 只给检测器 history[:t]（代码层面保证拿不到 t 之后的记录、拿不到环境内部状态和可用命令列表），记录它在哪些步报警。

**检测器**（从反应式到提前式）：

| 检测器 | 依据 | 角色 |
|---|---|---|
| R1 循环报警 | 连续 3 次相同动作 | 反应式基线（= 等到循环才知道） |
| R2 失败计数 | 同一目标连续失败 2 次（VBL 的 Diagnose 触发） | 已发表的半提前基线 |
| R3 首次失败 | 第一次 "Nothing happens" | 简单基线 |
| E1 名字核对 | 拿起的东西名字不在任务里 | 规则，只用历史 |
| E2 前提检查 | 用历史推出状态（在哪、拿着什么、开没开），检查动作前提 | 规则，只用历史 |
| E3 判断模型 | 小模型（OneJev 或 9B）只读历史，回答"agent 是否已经犯了让任务无法完成的错误" | 通用、不写规则 |

**指标**（按局 bootstrap 95% 区间）：
- 在循环开始前发现源头的比例（recall@before-loop）；
- 报警精度：报警的那一步确实是源头或源头之后、循环之前；
- 赢的局里每步的误报率；
- 提前量 t_L − d、滞后 d − e 的分布；
- 成本：每局额外的模型调用和 token。

**推翻 C2 的结果**：在误报率相同的条件下，只用历史的检测器（E1–E3）不比循环报警（R1）、失败计数（R2）更早，或者召回率很低。

## 6. C3：提前纠错是否更有效

**主比较**：F_d（检测器报警时纠错）vs F_L（循环开始后纠错），同一局、同一句纠错文字、同样的剩余步数。
**辅助比较**：O_e vs O_L（用正确动作纠错，排除"文字反馈写得好不好"的影响，只看时机）；F_e vs P_e（排除"任何提示都有用"）；N 组估计随机性。

**指标**：
- 主指标：干预后成功率（配对）。
- 次指标：干预后到成功的步数、token、**遵从率**（agent 下一步是否照着反馈改了）。遵从率可以检验一个机制：循环越久，历史里的错误模式越多，反馈越不容易被采纳。

**统计**：配对的成功与否用 McNemar 检验；多次重复用以局为随机效应的混合效应逻辑回归，报告效应量和 95% 区间。

**推翻 C3 的结果**：在相同剩余步数下，F_d 的成功率不高于 F_L；或者 F_e 不高于 P_e。
